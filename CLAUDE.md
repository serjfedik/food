# CLAUDE.md — правила работы с этим репозиторием

## Ветка
- Развивай на ветке `claude/sharp-wright-k5u79h`.
- **Никогда не пушь в `main` без явного разрешения пользователя.**

## Обратная связь в конце каждого ответа (обязательно)
В конце каждого хода явно перечисляй:
- что **осталось не доделанным** в текущей итерации;
- на **какие вопросы пользователь не ответил** (и без ответа двигаться нельзя);
- какие решения **«подвисли»** (ждут внешних действий: ключи API, доступы, мерж в main, ответы от вендора).

Если ничего не висит — короткая фраза «Хвостов нет».

Эту же сводку дублируй в `README.md` в раздел **«🕓 В работе / висит»** — чтобы новая
сессия в свежем контексте видела незакрытые хвосты.

## Раздел «О разработке»
- Структура — 4 вкладки: **О продукте / Сравнение возможностей / Статистика / Технологический стек**.
- Блок «Автор продукта» — отдельным блоком ПОД вкладками, всегда виден.
- Кнопка «📖 Открыть подробный гайд по приложению» — ПЕРЕД вкладками; включает режим
  гайда (`st.session_state["_about_guide"] = True`), заменяющий основной раздел.
- Реализация: контент в `src/about_data.py`, рендер в `src/about_ui.py`.
- **Правило синхронизации:** при добавлении нового пункта в сайдбар обязательно
  добавляется `_guide_section` в `_render_app_guide()`. Иначе гайд устаревает молча.
- **Roadmap-плитки:** реализованное СРАЗУ убирается. Не превращать в changelog.
- Содержимое плиток заполняется по фактам этого проекта — НИКАКИХ «AI-powered» /
  «enterprise-ready», если в коде этого нет.

## Файлы данных (расширяются, НЕ переписываются с нуля)
- `data/categories.json` — категории-плитки (ключ, лейбл, эмодзи, цвет).
- `data/nutrition_ru.csv` — БД продуктов для КБЖУ (name, aliases, kcal, protein, fat, carbs, piece_g).
- `data/starter_recipes.json` — стартовый набор базовых рецептов для матчинга в «Холодильнике».

После правки CSV/JSON напоминать пользователю про кнопку «🔄 Обновить кэш» в сайдбаре.

## Бэкап
- НЕ трогать без явной просьбы: `.github/workflows/cloud-backup.yml`,
  `.claude/hooks/cloud-backup.sh`, `.claude/cloud-backup.conf`, `.claude/settings.json`.

## Деплой
- Streamlit Community Cloud: при создании приложения нужно указать **актуальную ветку**
  (не `main`, если фичи ещё не смержены).
- Системные пакеты — в `packages.txt`. Python-зависимости — `requirements.txt`.
- Drive — сервисный аккаунт, секреты в Streamlit Cloud → Settings → Secrets
  (формат — `.streamlit/secrets.toml.example`).

## Качество кода
- Без лишних абстракций «на будущее». Three-similar-lines > premature abstraction.
- Без комментариев типа «что делает строка» — только «почему» (неочевидные инварианты).
- Тяжёлые импорты (PIL, pytesseract, googleapiclient) — **ленивые**: модуль должен
  грузиться, даже если зависимость не установлена, и падать понятной ошибкой только при вызове.
- Структура Recipe back-compatible: `from_dict` терпит отсутствие новых ключей.
